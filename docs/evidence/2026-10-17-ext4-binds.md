# ext4 `-b` through `neoproot-um` with this repository's `um-init` (2026-10-17)

One device run of `neoproot-um` on an ext4 image whose `/um-init` is the
harness's own `harness/um-init` (init protocol 2). The point is that the two
halves meet: the neoproot supervisor writes `/run/neoproot/binds`, this
repository's init declares `neoproot-init-protocol=2` / `feature=binds`, mounts
each record through hostfs, and the run fails instead of quietly losing a bind.

Device: Termux host (Xiaomi 23124RN87C, Android 15, kernel 5.15.194); kernel
`linux-bionic` `b778f4f7…`, `stub_exe` `731c48d5…`, `neoproot-um` `43566955…`.

Image: 64 MiB ext4 built on the container side with `mke2fs -d`, `/um-init` =
`harness/um-init` (`d1e8c223…`), static busybox plus the usual symlinks. The
image sha256 `82d77435…d254039` was unchanged after every run (each run used
its throwaway COW).

| run | what | result |
| --- | --- | --- |
| 1 | `-b dir:/mnt/hostdir`, `-b dir:/mnt/ro:ro`, `-b file:/mnt/file`, `-b file:/mnt/rofile:ro` | exit 0: guest read both host files, wrote into the rw directory, and got `Read-only file system` for both read-only bindings; the host saw the guest's writes; guest `/proc/mounts` shows all four hostfs mounts with the right `ro`/`rw`; `UMARM_BOOT_OK` |
| 2 | missing host source | supervisor refused before boot: `cannot resolve bind source ... No such file or directory`, exit 1, command never ran |
| 3 | target under `/proc` | supervisor refused: `invalid or duplicate option ...`, exit 1 |
| 4 | target under a regular file (guest-side failure) | the init wrote `UM_BIND_ERROR=/mnt/file/child:missing-target` and `UM_SESSION_ERROR=125`, command never ran; supervisor failed the run |

Raw logs: `2026-10-17-ext4-binds-run1.log` … `run4.log` in this directory.
Together with the soak and fault records, this is what the UM release's
`ext4-gate=pass` rests on. Device time for the whole check: about five seconds.
